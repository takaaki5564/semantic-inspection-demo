## 実装順序と責務

Step 1は必須の右側一覧です。Step 2は第一候補の3D色分けです。短期間で検査画像と分離できなければStep 3の簡易立体図へ切り替えます。Step 2とStep 3の両方を完成させる必要はありません。各段階で実行結果を確認します。

| モジュール | 責務 |
|---|---|
| Inspection Evaluator | 有効な観測を検証し、部位の観測条件・状態を判定する |
| Inspection State | 部位ごとの観測済み点、履歴、状態を保持し、表示用スナップショットを提供する |
| Inspection Planner | 必要な未観測点から次の視点を選ぶ。関節角や表示色を決めない |
| Inspection GUI | ID・名称・状態・coverage・次の撮影対象を表示する |
| Inspection Region Visualizer | 同じ状態スナップショットを3D色または簡易立体図へ反映する |

GUI内で可視性やcoverageを再計算しません。仮想カメラ／UR10eの切替は撮影実行側の差で、部位状態の意味は共通です。既存のセッション状態、知識ファイル、プランナーの入出力を部位状態名で置き換えません。

## 部位状態とcoverage

`coverage = 累積で有効に観測できた評価点の数 / その部位の必要評価点の数`です。同じ点の重複観測は加算しません。現在の仕様では対象部位の全63点が必要です。任意の成功割合を埋め込みません。

提案の`unconfirmed`、`partial`、`needs_recheck`には説明上重なる部分があるため、Step 1で評価器に実装する判定案を以下とします。これは未実装の設計であり、既存の判定結果を変更したものではありません。

| 状態 | 判定案（上から優先） | 表示色 |
|---|---|---|
| `not_required` | 今回の検査仕様の対象外 | 中立色・対象外の文字 |
| `confirmed` | 必要な評価点がすべて累積観測済み | 緑 |
| `partial` | 一部の必要点が累積観測済みで、未観測点が残る | 黄 |
| `needs_recheck` | 有効な撮影・評価履歴があるが、その部位の累積有効点は0 | 赤 |
| `unconfirmed` | その部位に反映できる撮影・評価履歴がまだない | グレー |

`confirmed`は今回定義した観測条件の充足です。製品の良否判定ではありません。後の視点から見えなくなっても、同一セッションで既に観測した点は保持します。`blocked`はセッションの停止理由であり、全部位を一律に赤へ変える指示ではありません。

古い画像、未到達、撮影中の形状変更など、無効と判定したフレームは観測へ反映しません。過去の有効な状態を保持し、異常は別途表示します。部品形状／検査仕様を切り替えると互換性のない履歴・次の撮影対象をresetします。

仕様Xで対象外のR2も一覧に表示しますが、coverageは`—（対象外）`とします。評価していない部位を0%や100%と見せません。部位名は明示したメタデータから取得し、Prim名の文字列を意味推論に使いません。

## Step 1：右側GUIの部位一覧

表示項目は部位ID、部位名称、観測状態、累積coverage、次の撮影対象です。状態は色付きラベルと文字で示します。初期化時と有効な観測反映後に一覧を更新します。

次の撮影対象は、選択済み計画の`predicted_new_point_ids`が空でない部位です。GUIが部品名から決めることはありません。予測で対象となっても、観測済み点やcoverageは増やしません。計画がない時点や完了・blocked・reset時は対象表示を解除します。

実装候補は次のとおりです。既存の基本GUIが先に実装される場合はその構成へ合わせ、同じ機能を重複させません。

- `src/inspection_region_state.py`：Isaac Simに依存しない部位状態データと、評価器側からの更新・スナップショット。
- `src/inspection_region_panel.py`：右側GUI。表示に徹し、画面操作で検査状態を書き換えない。
- `config/inspection_regions.json`：実在するR1/R2の名称などのメタデータ。Prim対応は実シーンの`SurfaceRegion`と照合する。
- 共通イベントへの接続：`session_started`、`observation_applied`、`plan_computed`、停止・resetを扱う。古いセッションのイベントを新しい部品表示へ適用しない。
- テスト・実行手順書：コア判定とイベント連携をIsaac Simなしで確認し、GUIは既存環境で確認する。

新しいGUI入口または明示的なオプションから利用し、既存Day 1〜4の起動方法・既定動作を維持します。GUI表示が撮影の物理時刻を進めたり、手先カメラの取付を変更したりしないようにします。step/run/reset等の基本操作とレシピ候補は、Day 5全体の計画と整合させます。

## Step 2：Prim単位の3D色分け

各region_idに対応した別USD Primを使います。現行R1Marker/R2Markerの対応を再利用できますが、**検査用の元Primの状態色変更は行いません**。そのまま変更すると検査RGBにも色が写ります。

表示モデルを分離し、状態ごとのグレー／黄／緑／赤を割り当てます。次の撮影対象は必要に応じ青い輪郭等で示します。GUIと同じ部位状態を参照し、可視性や確認済み判定を独自に作りません。

表示用Primを追加するだけでは分離は完了しません。現行の形状読み取りは`/World`配下の表示形状を走査するため、複製がレイ遮蔽やハッシュへ混入する可能性があります。RGBへの映り込み・影と、評価形状・物理への影響をすべて確認します。

分離方法の候補は、表示用モデルと検査用モデルを分け、ビューポートと検査RenderProductで表示対象を分離する方式です。USD purpose等の利用可否はインストール済みIsaac Sim 6.1.0.0のAPIと実動作を調べてから判断します。フレームの隙間で検査マテリアルを一時的に差し替える方式は採用しません。

分離を短期間で検証できない場合はStep 3へ切り替えます。検査対象の姿勢、元マテリアル、ロボット制御、評価形状を表示都合で変えません。

## Step 3：簡易立体図による代替表示

右側GUIに固定視点の部品模式図を表示します。既存環境で生成できる図でよく、自由回転や別アプリは不要です。ID、状態色、必要なら次の撮影対象を対応付けます。検査用RGBとは別の説明図であることを明示します。

この図も同じ部位状態スナップショットを使います。新しい欠陥ラベル、認識結果、成功率を作りません。Step 1の一覧は維持します。

## 受入確認とリスクへの対処

| 確認 | 期待する結果 |
|---|---|
| B/Y初回→後方撮影 | R1はconfirmed、R2はpartialからconfirmedへ。実観測に応じ累積coverageが更新される |
| A/Y | 初回でR1/R2がconfirmedになり、追加撮影対象が残らない |
| B/X | R1を評価し、R2はnot_required。対象外coverageを表示しない |
| 実観測が0点／無効フレーム | 評価履歴との区別に従い状態を判定。無効フレームで観測点を増やさない |
| アーム未到達・到達候補なし・動作禁止・上限 | blocked理由を表示し、観測状態を成功へ書き換えない |
| 重複観測・複数視点 | 重複点を二重加算せず、既観測点を保持する |
| A/B・X/Y切替、reset | 旧履歴・旧計画の強調を持ち越さない |
| 仮想カメラとUR10e | 同じ観測証拠には同じ状態判定・表示を使う |
| 一覧と3D／模式図 | 同一スナップショットのID・状態・coverageが一致する |
| 表示ON/OFF | 検査RGBに状態色・表示モデル・影が混入しない。評価三角形・ハッシュ・物理も表示で変化しない |
| 既存動作 | 既存の起動・撮影・可視性・計画のテストと適切なランタイム確認が通る |

主なリスクは、部位状態とセッション状態の混同、GUI独自判定、古いイベントの持越し、表示モデルのRGB／レイ遮蔽への混入です。追加の部位状態を既存状態から分離し、評価器・状態管理を唯一の根拠とし、セッション識別・reset・表示分離の確認で対処します。

対象外は任意メッシュの自動分割、複雑な面別マテリアル、高解像度カバレッジヒートマップ、高度な半透明描画、独立可視化アプリです。既存のロボット動作・撮影・再計画と、期限内のデモ完成を優先します。
